## What I built and updated

- **Live GSTIN/PAN lookup** (`ml/api/live_intake.py`, new) — deterministically
  simulates a plausible business profile + 24-month bank/GST/EPFO history
  from any GSTIN or PAN you give it. Same input always reproduces the same
  score (seeded from the identifier itself), so it survives a judge asking
  twice. Simulates exactly the fields requested from IDBI in
  `DATA-FIELD-REQUIREMENTS.md` — swapping this module for the real
  GSTN/Bank-AA/EPFO sandbox once credentials arrive is a drop-in change,
  nothing downstream (model, screening, decision policy) needs to move.
- **Wired it through every existing endpoint**, not just a new one-off route:
  a `LIVE-<GSTIN|PAN>` id is now a first-class `msme_id` — `/api/score`,
  `/api/msme/{id}`, `/api/graph/{pan}`, `/api/ocen/offer/{id}` all
  transparently handle it. Practically: the *entire* existing health card UI
  (score gauge, radar, reason codes, EWS, screening, entity graph, OCEN
  lending rail) now works for a live-looked-up business with no new frontend
  components — I only added an input form on `/console`.
- **Registry + entity-graph checks run on REAL data even for simulated
  financials.** Verified this live: scoring the real Maharashtra non-genuine
  GSTIN `27AABCT5678Q1Z9` through the new live-lookup path still correctly
  force-DECLINEs it, citing the actual government registry hit — even though
  its bank/GST history is simulated. That's the honest design: financials are
  a labeled placeholder, screening isn't.
- **New "Live lookup · any GSTIN or PAN" panel** on `/console`
  (`web/src/app/console/page.tsx`) — client-side format validation before
  navigating, so a bad identifier gets an inline error instead of a broken page.
- Extended the `ScoreResponse` type/schema with `simulated` /
  `simulation_note` fields (both endpoints and frontend) — same honesty-chip
  pattern the registry already uses for `is_sample`, never hidden.
- **Regression-tested**: all 3 existing personas (RAMESH001/SURESH002/PHOENIX003)
  score byte-identical to before. Screening self-test suite passes clean.
  Production build (`npm run build`) passes with zero TypeScript errors.
- Committed the round-2 planning docs from earlier this cycle that were still
  sitting untracked: `ROADMAP-ROUND2.md`, `TASKS-ROUND2.md`, `COMPETITORS.md`,
  `DATA-FIELD-REQUIREMENTS.md`, and the round-1 submission deck (`docs/deck/`).
- Pushed to `origin/main`.
